fix: bound the gallery-dl fallback, stop leaking exception text, rotate bot.log

- The gallery-dl fallback had no size ceiling. --max-filesize stops yt-dlp
  mid-transfer, but a link that fails yt-dlp three times and then resolves to
  a large gallery target wrote to disk until SUBPROCESS_TIMEOUT fired, because
  the handler's size check only runs once the bytes are already there. It now
  gets the same --filesize-max ceiling.
- A bare TimeoutError has an empty str(), so a retry sequence that timed out
  told the user "Transient error after 4 attempts: " with nothing after the
  colon. The exception name is now reported.
- The handler published str(exc) into the chat, where it can carry absolute
  container job paths or a fragment of the extractor's stderr. The detail stays
  in the log; the chat gets the outcome. Two tests that pinned the old
  behaviour now pin the new contract, and the HTML-in-exception test asserts
  the stronger property (nothing is rendered at all).
- bot.log grew for the lifetime of the process in the container's writable
  layer; it is now a RotatingFileHandler (5 MB, two backups), factored into
  _configure_logging so it is testable. Note that RotatingFileHandler never
  rolls over an empty file (gh-116263), so the test needs two writes to prove
  that it rotates.
